## 0 · 一句话

把"做一份能投影的 slide"这件事，从**每次重新发明**变成**填空** —— 而且不难看、不会翻车。

---

## 1 · 目标与不目标

### 要的

- **快**：新 deck 从复制到出稿，中间的尺寸/颜色/版式决策全部为 0
- **不错**：那些"错了看不出来"的东西（字号、对比度、导出兼容、容量）由系统保证
- **可传**：别人拿去也能用，不会走样

### 不要的

- 不要做成"万能模板"去适配别人已有的 deck —— 那会变成妥协的集合
- 不要一次性支持所有场景（多语言、多品牌、多比例）
- **不要在没有做过一份真 deck 之前重构文件结构**（见 §5-1）

## 3 · 已定的决策

**这些已经定过，不要重新讨论，除非有新证据。**

### 3.1 方法：从需求推导，不从现有 deck 归纳

从两份已有 deck 里提取交集，等于把"上次碰巧长成那样"当成规范。**实测证明这不一样**：推导过程找出 4 个颜色缺陷（包括两份 deck 都中招的 `--muted` 对比度），而归纳法永远发现不了"你们一直都错了"。

### 3.2 画布 1280 × 720，导出 960 × 540 pt

因为 **96dpi 下 CSS px 与 PDF pt 是 0.75 的整数比**：1280px → 960pt，720px → 540pt，一一对应，导出无缩放、无半像素模糊。

> （上一版这里写成"13.333in 是整数英寸 / A 系列纸张宽度"，是错的。A 系列是公制，13.333 也不是整数。纠正为上面的 pt 换算关系。）

### 3.3 字号是等比数列，公比 1.2，基准 `u`

不是"选的 52px"，是 `u × 1.2⁴`。按**角色**命名（`--fs-h1`），不按数字。

**且字号只能用阶梯上的值。** 阶梯之外的中间值（0.84u、0.76u、0.6u…）一律不许出现 —— 那等于绕过字号系统。这是修 §2-#1 时立的规矩。

### 3.4 `u` 由场地决定，不由审美决定

```
u = 7.447 × D / W      D=最远座位(m)，W=屏宽(m)
```

默认 `W=2.4m`、`D=8m` → `u = 25px`。

> **口径说明**：公式把 20 弧分施加在 **em 框**上，不是字形高度。中文 ≈17 弧分（达标），拉丁小写 x-height 只有约 10 弧分。若某份 deck 以英文小写为主，`u` 应上调约 1.4×。

**且 `u` 的有效上限是 25px，不是 28px。** 骨架也随 `u` 线性增长。实测：

| `u` | 正文区 | 骨架占比 | 模板自带 3 行条目表 | 判定 |
|---|---|---|---|---|
| 19 | 405.9 | 43.6% | ✓ | ✓ 舒适 |
| 22 | 357.4 | 50.4% | ✓ | ✓ 舒适 |
| **25** | **309.0** | **57.1%** | **+87px** | **✓ 默认，安全上限** |
| 26 | 292.3 | 59.4% | −14.4 ✗ | ✗ 示例页当场溢出 |
| 28 | 259.6 | 63.9% | −70.7 ✗ | ✗ |
| 31 | 211.1 | 70.7% | − | ✗ 放不下一个完整原型 |

> **上一版这里写的是「`u ≤ 28` 是硬上限」，错的。** 那张扫描表的“28 那一行能放 3 行条目表”是真的，但前提是你**得删行**；`PLAN` 转述时丢了这个前提，而 §5-4 又给了一条“把 `u` 改大然后跑 check”的命令——**照着做必然变红，而且文档里没有一个字说这是预期的、红了之后该干什么**。
>
> 现在示例条目表只放 3 行，`u` 到 25 还有 87px 余量。真正需要更大字（礼堂、户外）时，要换的不是 `u`，是**骨架本身**——先砍导语，再砍落点句。

### 3.5 所有间距都是 `u` 的倍数，没有第二个基准单位

页边距 `3u`、上边距 `1.75u`、下边距 `1.25u`、骨架块间距 `0.75u`、原型内部间距 `1u`。

**骨架间距必须比原型内部紧** —— 否则框架会吃光正文区。

### 3.6 颜色必须过对比度实测，不许凭眼睛定

门槛：正文 **≥4.5:1**，大字与图形 **≥3:1**，分隔线 **≥1.5:1**。

### 3.7 红色 `#a70e13`

红色采用 `#a70e13`，按使用背景检查对比度。

- 白底 **7.73:1** ✓ 很宽裕
- 深底 **2.37:1** ✗ → 深色页必须换提亮版 `#ee4248`（4.80:1）

**所以 `--accent` 不是一个值，是两个场景下的两个值。**

### 3.8 骨架六个锚点，只有正文区伸缩

这是"十页翻下来看起来像一套"的隐形功臣。落点句和导语都是可选的。

### 3.9 单文件自包含，零外部引用

不许 CDN、外链字体、外链图片。图片转 WebP 后 base64 内联。

### 3.10 一次按键 = 一页，不做逐元素动画

投影现场不给你重播的机会。

### 3.11 `check.py` 是发布前门禁

自动查：外部引用、`box-shadow`/`gradient`（剥注释后判）、逐页容量、PDF 软掩码与页面尺寸。
人眼查：逐页扫一遍，退到最远座位看最小一行。

### 3.12 演讲者 UI 不受 `u` 控制

`#notes` / `#help` / `.chrome` 不在 1280×720 舞台里，是 1:1 屏幕像素。**尺寸用固定 px，颜色走令牌。**

## 4 · 已否决的方案

**这些想过了，不要重试，除非前提变了。**

| 方案 | 为什么否决 |
|---|---|
| **从现有 deck 提取交集** | 固化偶然，且发现不了系统性错误（最早那版归纳法方案就是这条路，已废弃） |
| **拆成 `base.html` + `parts.html`** | ① 与 §3.9（单文件）+ §4（否决构建脚本）矛盾——合起来已推出"只能一个源文件"；② 拆的轴不对：病因是"CSS 混三层关注点"，却按"系统 vs 示例"切；③ 校验只能覆盖 `:root`，骨架和原型 CSS 照样各存两份；④ 净收益为负——为省一次"删 6 段"的动作，换来长期维护两份 19KB CSS |
| **`build.py` 构建脚本** | 手上只有两份 deck 就上构建系统，是过早抽象 |
| **Ghostscript 压缩 PDF** | 破坏 ToUnicode 映射表，文字变乱码，搜索/复制/读屏全废。体积不是真问题 |
| **`box-shadow` / `linear-gradient`** | 软掩码，部分阅读器渲染成实心灰块 |
| **四器官配色（紫/橙/绿/蓝）** | 与"白/黑/红色"三色主题冲突。改用**红色编号 + 头发丝分隔线** |
| **深色当"模式"** | 改成当**原型**（`.slide.dark` 只换令牌，不动结构）。深色只有一个用途：装深色截图 |
| **回改已发布的两份 deck** | 第一份 PDF 已分发，回改会造成版本混乱。统一从第三份开始 |
| **浏览器"打印 → 存储为 PDF"** | 绕过 `@media print` 里的修复，软掩码问题会回来。必须用命令行 |
| **真正的"演讲者视图"** | **理由修正：优先级低，不是技术脆弱。** 弹窗拦截只针对非用户手势的 `window.open`，绑在按键上不会被拦；页码同步用 `BroadcastChannel` 十几行就够。现在的备注是盖在幻灯片上的，镜像投屏会露馅——已知，接受 |

### 5-2 ✅ 字体 —— 已解决（2025-09 第三轮）

**结论：内联静态子集。** 它一次性解决了三件事，其中第三件是原来没想到的：

| | 原来担心的 | 实际 |
|---|---|---|
| 1 | 字体装没装 | `build_font.py` 从 16.9MB 变量字体子集化到 136KB，base64 内联 |
| 2 | 跨机器换行差一行 | 字体锁死 → 换行锁死 → `check.py` 的测量才有意义 |
| 3 | **PDF 的 Type 3** | **静态内联 → CID TrueType。146 个 Type 3 → 0，PDF 504KB → 85KB** |

**第 3 条是决定性的**：原来以为「PingFang 只能导成 Type 3」是死结，讨论过要不要换字体、
要不要用 Ghostscript 压（`/ebook` 能压到 645KB 但会破坏 ToUnicode）。**真正的解法不是换字体，
是把字体变成静态的再内联。**

配套：
- `build_font.py`（幂等，改完文字重跑即可）
- `check.py` 新增**字形覆盖检查** —— 内联之后改文案引入新字符，会静默掉回系统字体，
  屏幕上完全看不出来但 PDF 里会出 Type 3
- Type 3 数量不为 0 时 `check.py` 直接判失败

**拉丁字体决定：不用第二套**，理由见 RULES §2.5。

### 5-2b ✅ `什么是 Agent` 重做 = 模板的**第二次验收**（已完成）

**产出：`什么是 Agent/index.html`**（10 页 · 0 图片 · 0 深色页）· 它之前的旧模板版已删除

#### 验收发现了什么（这才是这一步的价值）

**① `.rows` 缺 `.tight` 变体** —— `.args` 早就有，`.rows` 一直没有。
四条带英文小注的条目 + 落点句这个组合，`.row` 的 0.44u 行内边距塞不下。
→ 新增 `.rows.tight`（0.24u，这个组合能站住的最大值），已提升进模板。

**② 落点句每多一行，正文区少 60.4px** —— 这是容量表里的隐藏前提。
容量表写「正文 + 落点句 = 334.8px」，但**没说前提是落点句只占一行**。
Agent deck 的 p3（1 行落点句）→ 334.8px，p4（2 行）→ 274.4px，**差正好一行落点句**。
→ 写进 `RULES §6`。**落点句写长了等于偷偷砍掉正文一行的容量。**

**③ `.loop .lnode` 最多 8 个中文字** —— 第 9 个字单独掉到第二行变**孤字**。
Agent deck 原来写「用眼睛看改成了什么」（9 字）就踩了。
→ 写进 `RULES §6 列宽硬约束`，并注明**孤字没有机械检查，只能渲图看**。

| `--fs-*` 写死 px | 改 `u` 不跟着变 | 全是 `u` 的倍数 ✓ |

> **旧令牌那个 `--muted` 值得单说**：它把页脚、英文小注、注解全放在 2.78:1 的灰上。
> 屏幕上勉强能看，**共享屏幕压缩之后基本消失**。RULES §5 早就点名过「两份已有 deck 都有这个问题」，
> 这次是把它真的修掉了。

#### 第二次验收的结论

模板**经得起一份跟它不同形态的 deck**（10 页 · 零图片 · 纯论述型）。
发现的三条都是**容量细节**，不是结构缺陷 —— 说明骨架和令牌设计是稳的。

**但样本还是只有 2。** 第三条验收样本之前不建议宣布模板定稿。

### 5-3 ⬜ 长期：让 styleguide 用令牌渲染自己

最早那版方案的 `styleguide.html` 把字号写成了 `style="font-size:54px"` + 手写的 `54px · 英文衬线` + 手写的 `--fs-h1`——**同一件事写了三遍**。加一行 JS 用 `getComputedStyle` 把实际像素填进去，改 `--u` 目录自动跟着变。

### 5-4 ⬜ 旧方案手里还有两样东西没吸收

- **四层模型**（不变量 / 令牌 / 原型 / 纪律）—— `PLAN §2` 抱怨过「CSS 混了三层关注点」却叫不出名字，**名字旧方案早就起好了**
- **23px ↔ 25px 的交叉验证** —— 23px 是从**真实失败**（初版 11–13pt 全部推翻）得来的经验值，25px 是公式推的，**两条互不相关的路径落在同一个窄区间**，这比 §3.4 那张自己测自己的扫描表有说服力得多

### 5-5 ⬜ 旧 deck 是否迁移

见 §6-3。**注意：`什么是 Agent` 第 6 页余量只有 8.4px，而且它的 `.body` 没有 `overflow:hidden`**——静默重叠那个坑在已发布的 deck 里还活着。

## 6 · 已定的输入

| # | 问题 | **决定** |
|---|---|---|
| **6-1** | 分隔线用哪种？ | **不用线** —— 靠行距、红色编号、粗体关键词分界 |
| **6-2** | 要支持到多窄的窗口？ | **900px → `u = 28px`**（后来定 28，见下） |
| **6-2b** | `--u` 到底取多少？ | **28px** |
| **6-6** | 拉丁字体 | **不用第二套 —— 拉丁也用思源黑体** |
| **6-3** | 已有的两份 deck 要不要迁移？ | 不迁移（PDF 已分发） |
| **6-4** | 以后的 deck 会不会只有中文？ | 假设中英混排 |
| **6-5** | 会不会放截图？ | 假设会，保留深色原型 |

### `u` 的两个约束（都实测过）

- **下限**由「要支持到多窄的窗口」定：`u = 22400 / Sv`，`Sv = 900px` → 25px
- **上限**由骨架占位定：`u = 26px` 时示例页当场溢出 −14.4px

**最终取 28px** —— 超出上面算出的 25px，代价是正文区从 309px 降到 260~420px，
导语和落点句从此只能二选一（见 RULES §6）。

## 7 · 做完了的标准

1. **顶部注释能在 20 行内说清文件由哪几段组成** —— 可测。（上一版写"`base.html` 能一屏看完"，是空头支票：令牌 + 引擎 + 骨架 + 全部原型 CSS 不可能一屏，除非把原型 CSS 拆走——那样抄来的零件就没样式了）
2. **`check.py` 全绿**，且对故意改坏的文件会报错（要测一次反向用例）
3. **不查文档能做完一份 deck** —— 拿 `template.html`，从零做一份 10 页，中途不需要回头问任何尺寸、颜色、版式问题

**第 3 条是真正的验收。** 前两条是必要条件，不是充分条件。

## 附 · 常用命令

```bash
# 自检
./scripts/check.py deck.html --pdf out.pdf

# 导出 PDF（不要用浏览器的"打印 → 存储为 PDF"）
CH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$CH" --headless=new --disable-gpu --no-pdf-header-footer \
      --virtual-time-budget=6000 \
      --print-to-pdf="Deck.pdf" "file://$PWD/deck.html"

# 逐页截图（人眼检查用）—— 用 1400×900 让 check.py 自己除以缩放系数，
# 不要用 1280×807 那种"减去 87px"的写法：那个数字是某次在某个
# Chrome 版本上量出来的，跨版本不稳，而且和 check.py 的做法不一致。
for n in $(seq 1 10); do
  "$CH" --headless=new --disable-gpu --hide-scrollbars \
        --force-device-scale-factor=1 --window-size=1400,900 \
        --virtual-time-budget=2000 \
        --screenshot=/tmp/s$n.png "file://$PWD/deck.html#$n"
done
```
