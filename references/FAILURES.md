## F1 · 1px 分隔线

**会发生**：在对方屏幕上，整条线消失。

**为什么看不出来**：你在自己屏幕上（全屏、未压缩）看它是完全正常的。
消失只发生在**经视频编码之后**——也就是对方看到的样子。

**实测**（1280×720 → 960×540，H.264）：

| 方案 | 原始对比度 | 编码后 | **存活** |
|---|---|---|---|
| **`1px #d0d0d0`** | 18.4% | **0.8%** | **4%** ✗ |
| `1px #a8a8a8` | 34.1% | 5.5% | 16% ✗ |
| `2px #d0d0d0` | 18.4% | 9.4% | 51% △ |
| `2px #b8b8b8` | 27.8% | **22.0%** | **79%** ✓ |
| `#f0f0f0` 底带 | 5.9% | 4.3% | 74% ✓ |
| `#e8e8e8` 底带 | 9.0% | 7.5% | 83% ✓ |

门槛：**≥8–10% 存活**算安全，4–8% 勉强，**<4% 死**。

**两条结论**：
1. **线宽比对比度重要。** `1px #a8a8a8`（原始对比度 34.1%）只剩 5.5%；
   `2px #d0d0d0`（原始只有一半）反而有 9.4%。
2. **用面，不用线。** 1px 线存活 4%，2D 底带 77–83% —— **差 20 倍**。

**根因**：4:2:0 的色度下采样 + DCT 量化。**是结构问题，不是带宽问题**（见下）。

**当前决定**：**不用线**。分界靠行距、红色编号、粗体关键词承担。

## F1b · 近白底色

**会发生**：几种「不同的东西」编码后**变成同一个颜色**。

**为什么看不出来**：屏幕上它们本来就是**非常接近**的几种浅灰，
靠 1px 边框区分。边一掉、色一压，就分不出来了 —— 而这两件事**同时发生**。

**实测**（老 Reviewer deck 的整套底色）：

| 老底色 | 原始 rgb | 编码后 rgb |
|---|---|---|
| `#fcfcfd` card | (252,252,253) | **(252,252,252)** |
| `#fbf9f8` band（**暖**） | (251,249,248) | **(252,252,252)** |
| `#fbfbfc` strip | (251,251,252) | **(252,252,252)** |
| `#fbf6f3` 强调行（**暖**） | (251,246,243) | (247,247,247) |
| `#f1f3f6` code（**冷蓝**） | (241,243,246) | (246,246,246) |
| **`#f5dfe0` accent-bg** | (245,223,224) | (249,227,231) ✓ 86% |

**四条全部塌成同一个中性灰。** 暖色偏、冷色偏、蓝色偏全被 4:2:0 抹掉。

**规则**：面要么**色偏 ≥20**，要么**灰阶差 ≥6**。最浅的活面是 `#f2f2f2`。
详见 `references/RULES.md §5 硬约束三`。

## F1c · 浅面用在深色页上

**会发生**：卡片、结论条在深色页上变成**一块亮斑**。

**为什么看不出来**：你是在**浅色页上**调的这个样式，深色页根本没翻到。

**规则**：每个面令牌都要有深色对偶（`--face-d` / `--face-2-d` / `--face-3-d`），
由 `.slide.dark` 切换。和 `--accent-d` 同构。

## F1d · 删 UI 时把 JS 弄死了

**会发生**：**整个 `<script>` 在抛异常的那一行死掉，后面所有代码都不执行。**
不报错、不弹窗、控制台不看就永远不知道。

**为什么看不出来**：症状看起来像「样式没加载」，不像「JS 死了」。

**实例**（真实踩过的）：

删调参面板时用了非贪婪正则 `<div id="pbtn">.*?</div>\s*<div id="panel">.*?</div>`，
`.*?` 只吃到**第一个** `</div>` —— **外壳删了、内容留在文档里**。后果链：

```
#panel / #pbtn 没了
   → getElementById('pbtn') 返回 null
   → null.addEventListener(...) 抛 TypeError
   → IIFE 当场死掉
   → 文件最后那几行全不执行：
        var h = parseInt(location.hash…)   ← 深链接失效
        S.forEach(… 填页码 …)               ← 页码空白
        fit(); apply();                    ← 舞台不缩放、页面不初始化
```

**症状**：舞台挤在左上角（`fit()` 没跑），旁边一堆裸文字按钮（孤儿 HTML 脱离子级定位），
按 `→` 还能翻页（**键盘处理器注册在崩溃点之前**）。

**怎么查**：`check.py` 现在会警告

```
⚠️  舞台没有被缩放（实际 1 · 预期 1.0938）
    deck 的 fit() 没有执行 —— 它的 JS 很可能报错死了。
```

**⚠️ 这条曾经污染过 `check.py` 本身**：探针原来假设 deck 的 `fit()` 已经把舞台缩放了，
然后拿缩放比去除。JS 一死，舞台没缩放，**所有容量读数系统性偏小 1/sc 倍（视口 1400×813 时是 9.4%）**。
现在改成**读真正生效的 transform 矩阵**，不再假设。

**规矩**：删 HTML 元素时，**用 DOM 结构配平（数标签）而不是非贪婪正则**；
删完**必须跑 `check.py`** —— 它是唯一会告诉你 JS 死了的东西。

## F1e · 逐页切换深浅

**会发生**：整本翻下来像**两套 deck 拼在一起**。

**为什么看不出来**：**单独看任何一页都是对的。** 深色页单独看甚至更好看 ——
深色让截图融进页面，不像贴上去的图。**问题只在翻页的连续体验里出现**，
而做 deck 的人是**一页一页做的**。

**实测**（Reviewer deck，8 页）：五页有截图，只有两页是深的。
这不是「两种底色混用」，是**同一种情况用了两种处理**。

**规矩**：**深/浅给整份 deck 一个统一答案，不许逐页切。** 见 `references/RULES.md §5 硬约束五`。

**`check.py` 抓不到这个** —— 它逐页量几何，没有「整本节奏」这个概念。
只能靠人翻一遍。

## F2 · `box-shadow` / `linear-gradient`

**会发生**：PDF 里出现**软掩码**（`/SMask` + `/Luminosity`）。

**为什么看不出来**：屏幕渲染完美。只有拆开 PDF 看对象结构才知道。

**原因**：PDF 没有原生的模糊/阴影表示。Chrome 导出时只能把那一块**栅格化**成一张带
alpha 的位图，附在页面上。后果：

- 打印时可能露出灰底（打印机把半透明拍成灰）
- 某些阅读器渲染出摩尔纹
- 文字变成图片，不可搜索
- 体积膨胀

**怎么查**：

```bash
python3 -c "
d=open('out.pdf','rb').read()
print('/SMask', d.count(b'/SMask'), '  /Luminosity', d.count(b'/Luminosity'))"
```

**两个都要是 0。**

**替代做法**：

| 想要 | 不要用 | 改用 |
|---|---|---|
| 卡片浮起 | `box-shadow` | 打印时 1px 细边框 |
| 行内高亮 | `linear-gradient` | 纯色 + `background-size` 垫在字下面 |

```css
/* 行内高亮：不用渐变也能量出「半高底色」 */
.hl {
  background-color: rgba(217,119,87,.30);
  background-repeat: no-repeat;
  background-size: 100% 44%;
  background-position: 0 92%;
  padding: 0 2px;
}
```

**图片同理**：带 alpha 的图要**拍平到背景色**再嵌入（`fig2-full` 就是这么修的：
alpha 拍平到 `#12151a`）。

## F3 · 用系统字体

**会发生**：PDF 里冒出几百个 **Type 3** 字体，体积翻几倍，文字变成逐字形绘图指令。

**为什么看不出来**：屏幕上**完全一样**。Type 3 也是正常渲染的字。

**根因**（这条容易搞错）：

> **不是 PingFang 的错，是「可变字体没有 PDF 表示」。**

Chrome 导出 PDF 时：
- **静态字体** → `CID TrueType` + Identity-H + 子集化 ✓
- **可变字体**（PingFang 是）→ 退化成 **Type 3**，逐字形画

**实测**：

| | 内联静态子集前 | 后 |
|---|---|---|
| Type 3 字体条目 | **146** | **0** |
| PDF 字体条目总数 | 152 | 4 |
| PDF 体积 | **504 KB** | **85 KB** |

**解法不是换字体，是把字体变成静态的再内联。**

**怎么查**：

```bash
pdffonts out.pdf | grep -c 'Type 3'     # 必须是 0
```

`check.py` 现在**直接判失败**（不再是打印一行完事）。

## F4 · 内联后改了文字

**会发生**：新引入的字符**不在字体子集里** → 静默掉回系统字体 → PDF 里又冒出 Type 3。

**为什么看不出来**：回退的也是黑体，字形几乎一样。**屏幕上完全看不出来。**

**这条最阴**：它不违反任何规则，你只是"改了个错别字"。
改动本身是对的，坏的是**没有人提醒你要重建字体**。

**实例**：在展示页文案里把「加导语就只剩 2 行」改成「加导语就只**剩** 2 行」、
「**无**导语可放 3 行」——`剩` `无` 两个字不在子集里，静默掉回 PingFang。

**怎么查**：

```bash
./scripts/build.sh deck.html       # 改完文字无脑重跑（幂等）：字体 → PDF → 验收一条龙
```

`check.py` 的 `font_coverage_check` 会解码内联的 base64、提取 deck 里所有可见字符、
逐个比对子集覆盖，报出漏掉的字。

## F5 · `.body` 没写 `overflow:hidden`

**会发生**：内容超出正文区，**静默压住页脚**，两者叠在一起。

**为什么看不出来**：你可能永远不翻到那一页。而且导出 PDF 时 Chrome 反正会裁切，
**所以从 PDF 上也看不出问题**——只有真去放映那页才发现。

**现状**：`assets/template.html` 里已经有 `overflow:hidden` ✓。
但早期一份已发布的真实 deck 第 6 页没有，余量只有 **+8.4px** ——
**这个坑在真实 deck 里是活着的。**

**依赖**（会一起动的三处）：

```css
.body { flex: 1; min-height: 0; overflow: hidden; }
/*      ↑ 撑满   ↑ flex 子元素会溢出   ↑ 咬掉溢出 */
```

少了 `min-height: 0`，`flex: 1` 撑不下去；少了 `overflow: hidden`，撑下去了但直接叠出来。

## F6 · 截图窗口给了 `1280,807`

**会发生**：裁 `(0,0,1280,720)` 时把页脚切掉。

**为什么看不出来**：你看到的是"一张少了页脚的截图"，看起来像是排版问题，不像截图问题。

**原因**：舞台在视口里**垂直居中**。窗口高 807 → 舞台落在 `y = 43.5 .. 763.5`，
`y = 763.5` 之后的内容不在你裁的框里。

**做法**：**一律 `--window-size=1280,720`**，舞台正好铺满，裁都不用裁。

## F7 · UI 没在打印时隐藏

**会发生**：调参按钮之类的固定定位 UI 被打进 PDF。

**修法不是列举名字**（下次加 UI 就漏了）：

```css
@media print {
  body > *:not(#stage) { display: none !important; }
}
```

**反向写法**："只保留舞台"。以后加任何 UI 都自动被排除。

## F8 · 直接编辑大文件改页面

**会发生**：你要给页面找唯一锚点，而一份 deck 约 440 KB、其中约 400 KB 是内联字体的
base64。锚点一旦找错（重复了、或者下一页改完把上一页的锚点吃掉了），**结果不是报错 ——
是内容被替换掉一截，或者 `</section>` 被吞，页面静默合并。**

**为什么看不出来**：文件仍然是合法的 HTML，`build.sh` 仍然通过，**页数甚至还是对的** ——
只是某页少了最后一段。要翻到那一页看才发现。

**实例**（冷启动测试的原始记录）：一个**只拿到这个目录、没有任何对话上下文**的 agent，
在四个回合里把同一段切片脚本重写了**四遍**：

```python
stage = pathlib.Path("pi-agent.stage.html").read_text()
A = '<div id="stage">'; B = '</div><!-- /#stage -->'
a = h.index(A)+len(A); b = h.index(B)
h = h[:a] + "\n" + stage.strip() + "\n" + h[b:]
```

它自己发明了「stage 文件 + 切片脚本」这套流程 —— **因为工具链给了起手、构建、验收，
唯独没给「写页」。** 下一份 deck 会重新发明一次，而且可能发明得更差。

**怎么查**：现在有 `setpages.py`：

```bash
./scripts/setpages.py deck.html --extract   # 页面抽到几 KB 的文件里改
./scripts/setpages.py deck.html             # 贴回去
./scripts/setpages.py deck.html --check     # 只体检
```

它保证 **边界以外逐字节不动**（抽出来再贴回去 `md5` 不变），写盘前自检五项：
外壳前后逐字节比对 · 页面数 · 幂等 · 页面区不含边界标记 · `<section>` 配平。
**任何一条不过就不写文件。** `check.py` 另外会查 `#stage` 边界是否唯一。

**规矩**：**永远不要用编辑器直接改 deck 的页面区。** 页面是数据，用 `setpages.py` 进出。

## F8b · 忘了改外壳里的 `<title>`

**会发生**：deck 的 `<title>` 还是模板的 `幻灯片规范 · 零件库`。**页面上完全看不见** ——
它只在浏览器标签、窗口标题、PDF 元数据里出现。

**实例**：四次冷启动测试，**每个 agent 用了不同办法去改它**：

| | 结果 | 怎么做的 |
|---|---|---|
| 第一次（人跑的） | ✓ `Pi Agent 简介` | 拼在自己的切片脚本里一起改 |
| A | **✗ `幻灯片规范 · 零件库`** | **忘了改** |
| B | ✓ `Write it down, or do it twice · 为什么架构决策要写下来` | **自己写了一段 Python heredoc**（带 `assert count == 1`） |
| C | ✓ `为什么延迟比吞吐更重要` | 直接 `edit` deck |

**同一个问题四种解法、两种结果 —— 这说明工具链缺一个入口，不是 agent 粗心。**

**⚠️ 更糟的是：两份已发布的真实 deck 也是这个状态。**
写这条检查的时候才发现的 —— `check.py` 一上来就把它们判失败：

```
✗ title 还是模板的（'幻灯片规范 · 零件库'）—— 交付物里不该有开发档案
    改：./scripts/setpages.py <deck> --title '这份 deck 的全名'
```

**怎么查**：`check.py` 现在**判失败**（`template.html` / `demo.html` 例外，那个标题是对的）。
修：`./scripts/setpages.py <deck> --title '…'` —— 只换那一个标签，页面区和外壳其余部分逐字节不动。
起手时也可以直接 `./scripts/newdeck.py out.html "deck 全名"`。

**规矩**：**`<title>` 是「这份 deck 的内容」，不是外壳。**
`setpages.py --title` 是唯一允许碰外壳内容的地方（因为它是内容），而且只换一个标签。

## F8c · 插页面时锚点命中别处：目录插到了封面之前

**会发生**：用脚本往 deck 里插一页（比如目录）时，锚点用的是**字串**而不是**结构位置** ——
那个字串在文件更早的地方也出现过，于是插到了错误的位置。页面上依然「每页都正常」，
**只是顺序错了**。

**实例**（2026-09-17）：给两份旧 deck 补目录，锚点用的是「第一个正文 section 的 kicker」：

| deck | 锚点 | 结果 |
|---|---|---|
| Agent | `01 · 误区` | ✓ 只出现在第一个正文节 → 插对 |
| Reviewer | `Why` | ✗ **封面标题就是 `Why your plan needs a smarter reviewer`**，`str.find()` 命中封面 → 目录被插到封面之前 |

**为什么没被抓住 —— 两道防线同时失效**：

1. **目检**：那一步确实渲染了第 2 页的图，而当时第 2 页是封面 —— **却把它读成了目录**。
   看过了，不等于看对了。
2. **`check.py`**：当时只查容量 / 字体 / 掩码，**不查页面顺序**。

**怎么查**：`check.py` 现在**判失败**：

```
✗ 第 2 页不是目录 —— 目录必须紧跟封面（RULES.md 页型表）
```

修：`setpages.py --extract` → 把目录 section 移到封面之后 → 贴回（顺序断言写在脚本里，别靠眼睛）。

**规矩**：**脚本插页时，锚点要用「第 N 个 section」这种结构位置，不要用字串。**
非要用字串，就先 `assert` 它在全文只出现一次；**插完再按结构断言一遍**
（第 1 段是 cover、第 2 段是 toc）—— 而不是渲染一张图用眼睛看。

## F9 · 模板示范页本身的余量很大

**会发生**：模板有两页余量到 **+148.8px**（第 12 页）/ **+146.6px**（第 2 页）——
视觉上是半页空白。**新 deck 会照抄这个密度**，因为它以为「示范页 = 标准」。

**为什么看不出来**：单看一页，大余量像是**故意的留白**（设计感）。要**连着翻几页**
才发现整本是稀的。

**实例**：冷启动测试做出来的 deck，p4/p8/p10 余量 **+172 / +136 / +142px**，
卡片摆在上面、落点句钉在底下，中间两百像素的空洞。`check.py` 全部报 ✓。

**怎么查**：`check.py` 现在**余量 > 45% 会警告**（不判失败 —— 它是判断题）。

**45% 这条线是量出来的**，不是拍的：

| | 最大余量 |
|---|---|
| 模板自己 12 页 | **42%** |
| B / C / A（冷启动） | 29% / 37% / 40% |
| **第一次冷启动的 p4** | **51%** ← 唯一视觉上明显半页空着的 |

**零误报**：八份 deck 七份全过，只点名那一页。

**⚠️ 我一度以为 41% 的页也空** —— 但模板自己的 p6 就是 42% 且看着正常。
**单看一页会高估这个问题**，所以阈值只能定在「明显不对劲」的那一档。

**规矩**：**余量超过正文区一半，这一页就该加点内容或换个原型。**

## F10 · 元素在 DOM 里，但渲染不出来

**会发生**：一个元素明明写进了 HTML，**页面上完全没有**。不是被裁切、不是颜色不对 ——
是它的盒子宽度被算成了 0。

**实例**（加 `.cap` 示范页时踩的）：模板第 8 页的正文区被内联改成横排 flex：

```html
<div class="body" style="display:flex;align-items:flex-start">
  <div class="shot" style="width:100%;…">截图放这里…</div>
  <p class="cap">图注：…</p>          <!-- ← 宽度 0，看不见 -->
</div>
```

`.shot` 是 `width:100%` 的弹性项，占满整行；`.cap` 是同级的第二个弹性项，
**分到 0 宽**，于是它折行折到看不见的地方去了。

**为什么看不出来**：DOM 里有、`grep` 找得到、`check.py` 的静态检查全过。
**只有渲图才看得见。**

**⚠️ 怎么发现的**：加完 `.cap` 跑 `check.py`，**容量数字一点没变**（还是 185.6）——
一个 16px 的段落加进去，正文区高度不可能不动。**「加了东西但数字不动」就是线索。**

改用 `flex-direction:column` 后立刻变成 220.0 ✓ 这 34px 就是那条图注。

**怎么查**：

1. 加元素前后各跑一次 `check.py`，**看容量数字有没有变**。没变 = 没渲染。
2. 弹性容器里放两个块，用 `flex-direction:column`，不要靠 `width:100%` 硬撑。
3. **渲图看一眼** —— 这条只能靠眼睛。

**规矩**：**DOM 里存在的元素，一定会在容量数字里留下痕迹。**
数字不涨的地方，就是有东西没画出来。

## F11 · 命令行工具把 `--help` 当成文件名

**会发生**：脚本用裸 `sys.argv` 取参数，没拦选项 —— 于是 `newdeck.py --help`
**生成一份名叫 `--help` 的 deck 文件**，然后打印一串莫名其妙的「下一步」。

**为什么这条值得记**：它不危险，**但它让 agent 的第一次接触就是一次失败**。
而 agent 在陌生工具上的第一次尝试失败后，会开始怀疑整套工具，绕路走。

**实例**：冷启动测试（第四次）里，agent 起手就试了 `newdeck.py --help`，
踩到之后在自己的报告里专门列了一条：

> **2. `newdeck.py --help` 不是帮助，它会生成一个名为 `--help` 的 deck 文件。**
> 我起手时踩到了，已删掉。

**同一次测试里 agent 还报告了另一条**（它遇到的 `SLIDE_FONT_DIR` 被设成不可写路径 ——
那是我为了测「缺字体」故意设的，**它识别出来了、绕过并说明了**）：

> `--doctor` 因此报「缺字体」，`build.sh` 会当场停在第 ① 步前。
> 字体其实一直在 `~/.cache/slide-fonts/`。我全程用 `SLIDE_FONT_DIR=…` 绕过了。

**怎么查 / 怎么防**：

```bash
# 每个脚本都要能安全地回答这三件事
./scripts/newdeck.py --help      # 打帮助，不生成文件
./scripts/newdeck.py --bogus     # 报错 + 打帮助
./scripts/newdeck.py             # 没有参数时也打帮助
```

**规矩**：**脚本里不要用裸 `sys.argv`。** 用 `argparse`，或者至少显式拦掉
`-h` / `--help` / 任何以 `-` 开头的参数。**一行代码，省掉 agent 的第一次失败。**

## 被证伪的假设

**这几条是花过时间的死路。别重走。**

### ✗ 提高码率能保住细线

测过 400k 和 3000k，**输出字节完全相同** —— 因为编码的是 30 帧相同画面，
码率约束从不生效。

**但结论反而更强了**：细线的消失是 **4:2:0 色度下采样 + DCT 量化**的结构问题，
**不是带宽问题**。带宽再多也救不回一个 1px 的细节。

### ✗ 换字体能解决 Type 3

治标。根因是**可变字体没有 PDF 表示**，换一个可变字体一样出问题。
解法是"把字体变成静态的再内联"（见 F3）。

### ✗ 用 Ghostscript 压 PDF

`/ebook` 能把 2.6 MB 压到 645 KB，**但会破坏 ToUnicode** —— 文字不可搜索、不可复制。
PDF 是拿来分发的，不能牺牲可搜索性。**拒绝。**

### ✗ 从现有 deck 归纳模板

**否决**。理由是个逻辑陷阱：`assets/template.html` 的零件有很大一部分正是从
一份真实 deck 提炼的（43 类里 41 类来自它），**拿同一份 deck 验收必然全绿**，
得不出任何信息。

所以这套模板是**从需求推导**的，不是从现有 deck 归纳的。

### ✗ 拆 base / parts 两套模板

维护两套同步的成本大于收益。**一个模板 + 一份令牌说明**够用。

## 一条方法论（为什么这张清单存在）

**每次纠结都变成一次实测，而不是一次辩论。**

| 纠结 | 做法 |
|---|---|
| 选哪个字体 | 测 48px 下同一串英文各占多宽、测断行位置 —— 不看"好不好看" |
| 分隔线怎么画 | 搭 H.264 编码台，数存活像素 |
| PDF 为什么大 | 不猜，`pdffonts` 数 Type 3 |
| `u` 取多少 | 从窗口宽度反推下限，用溢出实测卡上限 |

**推论：实测要能证伪自己。** 上面"提高码率"那条就是 ——
我们本来想证明"给够带宽就行"，测完发现码率参数根本没生效。
**结论从"带宽不够"变成了"带宽无关"**，反而更硬。
